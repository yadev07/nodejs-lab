Question 1: How does today's EventEmitter work connect to the Observer Pattern discussed in Theory Class 5?
Answer: Node.js's EventEmitter acts as a direct implementation of the Observer Pattern. In this setup, the EventEmitter object serves as the 'Subject' (or observable) that maintains a registry of dependencies. The listener functions acting via `.on()` or `.once()` serve as the 'Observers'. When the subject changes state or triggers an action via `.emit()`, it automatically iterates through and broadcasts notification messages to all subscribed observers sequentially.

Question 2: Name one core Node.js API (other than EventEmitter itself) that is secretly built on this same pattern, and explain how you know.
Answer: The 'fs' (File System) Streams API or the 'http' server module is secretly built on top of EventEmitter. For example, when creating an HTTP server using `http.createServer()`, the server instance inherits from EventEmitter. We know this because we interact with it using event hooks such as `server.on('request', ...)` and `server.on('error', ...)`. This confirms that network behaviors in Node.js are built around asynchronous event emitters reacting to underlying stream cycles.
